# Витрина парка

Реализовано 9 октября 2026 года. Маршрут Vite: `/p/:tenantId`, например `/p/phuket-drive`. Дизайн наследует `/app`; данные не копируются из глобального каталога Sunny. Витрина читает актуальные технику и брендинг парка при открытии/перезагрузке.

## Что работает

- Логотип и название парка, загруженные фотографии, базовая суточная цена и депозит.
- Поиск по названию/марке/модели, фильтр по типу транспорта, просмотр всех фото в диалоге.
- Состояния загрузки, ошибки, пустой витрины и отсутствующего фото.
- Просмотр в обычном браузере без Telegram и регистрации.
- Публичная витрина только для парков `trial`/`active` и явно опубликованной техники; скрытая, архивная и сервисная техника не выдаётся публично.
- Закрытое превью для подготовки черновиков. Превью не публикует парк, не меняет данные и не запускает trial.

## Как открыть

1. В `/platform-admin` открыть нужный парк.
2. Нажать «Подготовить превью витрины», затем «Открыть закрытое превью».
3. Ссылка действует час, показывает также черновики, но не позволяет менять парк.
4. Для публичного просмотра в редакторе каждой машины включить «Показывать на витрине» и сохранить.
5. Опубликовать парк, если он ещё черновик. Публикация по существующей логике запускает trial.
6. Отправить публичный адрес `/p/<tenantId>` без фрагмента `#preview=...`.

Существующие машины автоматически публичными не становятся. Для Phuket Drive уже есть ID `phuket-drive` и 3 единицы в локальных данных; содержимое live-хранилища этой задачей не менялось.

## API и безопасность

- `GET /api/storefront/{tenantId}` — только белый список публичных полей.
- `GET /api/storefront/{tenantId}/media/{reference}` — только обработанные WebP, явно связанные с видимой техникой или логотипом этого парка. Оригиналы и неиспользуемые файлы закрыты.
- `POST /api/platform/tenants/{tenantId}/storefront-preview` — требует текущую Bearer-сессию суперадминистратора.
- Превью передаётся в `X-Storefront-Preview`. Ссылка хранит capability в URL fragment, который не отправляется серверу в URL запроса; токен не передаётся в query-параметрах картинок.
- Подпись превью использует отдельный HMAC-ключ, производный от настроенного секретного ключа с отдельным назначением. Превью одного парка не работает для другого и не принимается в административном API. Права выпустившего администратора и срок действия повторно проверяются.
- Витрина подключается вместе с существующим `PLATFORM_ADMIN_API_ENABLED`; новых `.env`-переменных не требуется. При выключенном флаге публичный API тоже отсутствует.
- Ответы каталога и медиа не кэшируются; права на показ проверяются заново. Витрины пока `noindex`, вне SEO-каталога Sunny.
- При открытии `/p/` не вызываются глобальная загрузка каталога и Telegram lead-track/автостарт ИИ Sunny.

## Публикация и маршрутизация

`deploy.sh` подготовлен для копирования SPA-входа в `/p/index.html` и `/p/<tenantId>/index.html` существующих локальных парков. Скрипт в этой задаче не запускался.

В `deploy/nginx.sunny-rentals.online.conf` добавлено правило `/p/ → /p/index.html`, чтобы новые парки работали сразу без повторной frontend-сборки. Эта конфигурация — только файл репозитория. Обычный deploy её не устанавливает: отдельно уполномоченный администратор должен проверить/применить правило к действующему virtual host. Без него статические входы позволяют открыть уже существовавшие при сборке парки, но новые парки после сборки могут попасть на маркетинговую главную.

Production, Nginx и сервисы не изменялись и не перезапускались.

## Что не включено

Бронирование, проверка свободных дат, tenant-календарь, владелец с логином/паролем, общий Telegram-бот и tenant-aware ИИ — следующие отдельные этапы. Кнопка «Посмотреть» не выдаётся за бронирование. Чужие рейтинги, акции, отзывы, условия оплаты и доставки Sunny не переносятся.

## Проверки

Тесты `backend/tests/test_platform_storefront.py` используют исключительно временные данные: публичная проекция, три машины в превью, публикация/снятие видимости, исходные и чужие медиа, архив, закрытые парки, подпись, срок жизни, отзыв администратора, symlink/path isolation, отсутствие побочных папок для неизвестного парка.

Vite-сборка выполняется только через `npm run build:vite -- --outDir /tmp/...`: обычный `npm run build` запускает deploy и для проверки не используется. Новый frontend отдельно проверяется TypeScript и ESLint; общий TypeScript остаётся заблокирован существующим синтаксисом `src/types/crm.ts`. Браузер/скриншоты в окружении отсутствуют: визуальные проверки после публикации на телефоне и десктопе остаются обязательными.
