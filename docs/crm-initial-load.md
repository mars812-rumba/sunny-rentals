# Первая загрузка CRM — 31 октября 2026

В `CRMPage.loadMainData` убран второй запрос `/api/crm/users?status=...`.
Общий список пользователей нужен для индикаторов всех вкладок; текущая
вкладка теперь фильтруется из этого же нормализованного снимка — аналогично
существующему автообновлению. Legacy-статусы нормализуются тем же helper.
Confirmed определяется статусом лида, не наличием бронирования.

Раньше: запрос всех пользователей, затем параллельно текущая вкладка и
статистика. Теперь: один общий список и статистика стартуют параллельно.
Количество стартовых запросов данных снижено с трёх до двух, убран один
последовательный сетевой этап. Ошибки статистики не скрывают полученный
список. Общий AbortController сохранён: устаревшие ответы при смене
периода/вкладки или закрытии страницы не применяются.

Проверки без браузера: 16 Node-тестов загрузки, переходов/непрочитанных и
редактора рассылки; сборка CRMPage в памяти через esbuild; diff-check.
Новые тесты исполняют настоящий callback с управляемыми ответами fetch,
проверяют параллельный старт, количество запросов, все четыре вкладки,
legacy-статусы, HTTP/JSON/network ошибки и гонку старого/нового запроса.

Это не измерение времени первого открытия на телефоне. Заявленные
владельцем ~2 секунды пока не разложены на загрузку JS, сеть, API и render.
Браузер не запускался; фактический результат оценивается после публикации.

Менялся только frontend. Для этой правки backend перезапускать не нужно;
нужна публикация новой frontend-сборки. Публикация агентом не выполнялась.
