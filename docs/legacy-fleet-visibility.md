# Показ машин в старой витрине Sunny

## Исправленная цепочка

Поле `available` означает публикацию в каталоге, а не занятость на даты.
Явное `false` скрывает машину; отсутствующее поле или `null` в старых данных
сохраняет прежнее поведение — машина видима. Бронирования не изменяются.

- Оба экрана управления (`CarsPage`, `AdminPanel`) получают полный список через
  `/api/admin/cars`, независимо от наличия старого токена в localStorage или key
  в адресе страницы. Доступ к самим страницам/API по-прежнему защищает сервер.
- Переключатель отправляет только `{available: boolean}` через
  `PATCH /api/admin/cars/{id}/visibility?key=...` с `admin_required`.
- Сервер читает запись внутри `_lock`, меняет только available/updated_at и
  сохраняет её. Строки "false", числа и null не принимаются как boolean.
- Интерфейс меняет состояние после подтверждения сервера, блокирует повторное
  нажатие для той же машины на время запроса и показывает ошибку при сбое.
- `/api/cars` и `/api/available-cars` не отдают скрытые машины. Админский список
  сохраняет их для повторного включения. Старые брони и календарь не удаляются.

## Где изменение видно

После применения backend/frontend каталог `/app` учитывает переключатель при
следующей загрузке данных/обновлении страницы. Уже открытый каталог другого
клиента не обновляется push-событием.

Основной Next.js-сайт статически экспортируется: адаптер marketingCars также
исключает available=false, но результат изменится **при следующей сборке и
публикации сайта**, не мгновенно при щелчке в CRM. Автоматический deploy при
переключении не добавлялся.

## Проверки и применение

Четыре HTTP-теста в `backend/tests/test_legacy_car_visibility.py` используют
временный JSON и изолированный FastAPI: скрытие, включение, сохранность остальных
полей, публичные/админские ответы, категории и ошибки авторизации/валидации.
Пять Node-тестов `tests/car-visibility.test.mjs` проверяют клиентский запрос,
подтверждение, ошибки и повторные нажатия, обе страницы управления, адаптер
маркетинга и сборку изменённых экранов в памяти.

Production JSON не менялся; deploy, перезапуски и браузерные проверки не
выполнялись. Для применения нужны backend и frontend; внешний вид проверяет
владелец после применения. Не требуется перезапуск Telegram-бота только ради
этого переключателя — изменение обслуживает API.
