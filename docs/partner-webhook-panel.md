# Подключение общего бота из суперадминки

## Что добавлено

На главном экране `/platform-admin`, над списком прокатов, расположен блок
«Общий бот парков». Внутри конкретного парка остаются клиентская ссылка и
приглашение владельца; webhook не настраивается отдельно для каждого парка.

1. Нажмите «Проверить подключение»: сервер проверит `getMe` и `getWebhookInfo`.
2. Если webhook отсутствует, нажмите «Подключить бота» и подтвердите действие.
3. Если наш адрес уже установлен, «Обновить подключение» повторно установит
   текущий секрет из серверного окружения.
4. При другом адресе операция запрещена, даже при прямом вызове API.
5. После подключения отправьте `/start` боту. Для открытия определённого парка
   используйте его клиентскую ссылку, для прав владельца — личное приглашение.

Надпись «Наш webhook установлен» подтверждает регистрацию URL, а не успешный
сквозной ответ бота. Очередь и наличие прежней ошибки доставки показаны отдельно.
Дата последней ошибки может относиться к старому сбою. Нужна проверка новой команды.

## Архитектура и безопасность

- `backend/platform_core/partner_webhook.py`: ограниченный Telegram-клиент,
  проверка соответствия токена bot ID и username; фиксированный адрес из
  `PLATFORM_PARTNERS_PUBLIC_ORIGIN` плюс `/api/partners/webhook`.
- `backend/platform_partner_api.py`: `GET /api/partners/admin/webhook` и
  `POST /api/partners/admin/webhook/connect`, только действующая Bearer-сессия
  суперадминистратора. Owner/customer доступ запрещён.
- `src/api/park-telegram.ts`: административные запросы; токен Telegram и
  webhook-секрет не передаются в браузер.
- `src/components/platform/PlatformBotConnection.tsx`: проверка по кнопке,
  подтверждение подключения, состояния загрузки/ошибок, отмена запросов при уходе.
- `src/pages/PlatformAdminPage.tsx`: размещение общего блока вне карточек парков.

Проверка статуса не меняет Telegram. Подключение вызывается только по явному POST,
не при импорте модуля, старте приложения или открытии панели. `setWebhook` использует
`allowed_updates=["message"]` и `drop_pending_updates=false`: очередь не очищается.
Старый Sunny-бот не затрагивается. Нет endpoint для произвольного URL, удаления
webhook или принудительной замены другого адреса.

Сетевые таймауты ограничены; HTTP redirects запрещены. Сырые ошибки Telegram и
чужой webhook URL не возвращаются пользователю: они могут содержать секреты.
Если регистрация прошла, но последующая проверка не удалась, панель покажет ошибку:
сначала повторите проверку, не считайте это гарантированным откатом регистрации.

## Проверки

`backend/tests/test_partner_webhook.py`: только fake Telegram и временные данные.
Проверяются административная авторизация, отсутствие сети до авторизации,
совпадение bot identity, чужой webhook, фиксированный URL, секрет, сохранение
очереди, обновление своего адреса, таймауты и отсутствие утечек.
`tests/park-telegram.test.mjs`: Bearer, фиксированные маршруты, AbortSignal,
ошибки 409/503, отсутствие секретов в теле запросов.

Production deploy, restart и реальная регистрация webhook при разработке не
выполняются. После отдельной публикации требуется проверка на телефоне.
