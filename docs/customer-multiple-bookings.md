# Несколько заявок клиента и отмена

Клиент может оформлять несколько независимых заявок, в том числе при уже
подтверждённой броне. `/start` всегда открывает выбор транспорта и учитывает
параметр перехода из каталога. Заявка не заменяет другие заявки автоматически.
Точный повтор автомобиля и периода в offer/admin-create остаётся защитой
от повторной отправки; другой автомобиль или изменённые даты разрешены.
Проверки реальной занятости машины на даты не отключены.

Управление в личном Telegram-чате: кнопка «Мои заявки / отменить» в стартовом
сообщении и уведомлении о получении заявки; также команда `/bookings`.
Список содержит все активные заявки, по десять с кнопкой следующей страницы.
Каждая карточка содержит номер, машину, даты и состояние.

Отмена требует отдельного подтверждения:

- `new` / `pre_booking`: меняется только выбранная заявка на `cancelled`.
- `confirmed`: сохраняет статус и занятость; записывает
  `cancellation_requested_at` и отправляет запрос менеджеру.
- Повторное действие не меняет данные и не повторяет уведомление.
- Другие заявки и платежи не меняются, автоматического возврата денег нет.

API `/api/customer/bookings/{user_id}` и POST
`/api/customer/bookings/{user_id}/{booking_id}/cancel` требуют
`X-Booking-Bot-Token`, проверенный против настроенного `WEBAPP_BOT_TOKEN`.
Без настроенного секрета доступ запрещён. Telegram-бот берёт `user_id` из
отправителя; API отдельно проверяет владельца записи. Отмена сохраняется
под блокировкой; подтверждение и отклонение перечитывают состояние под
блокировкой, чтобы старая кнопка не возродила отменённую заявку.

Менеджеру отправляется уведомление о самостоятельной отмене или запросе
отмены подтверждённой брони. При сбое Telegram запрос остаётся в данных:
`cancellation_requested_at`; доставка уведомления не является транзакцией
с записью данных. Клиент видит сохранённый запрос в `/bookings`.

CRM сохраняет `confirmed`, если есть другая подтверждённая бронь;
`pre_booking`, если остались заявки; иначе `in_work` (не архивирует клиента).
Claude получает контекст всех активных заявок и не должен считать наличие
одной брони запретом новой. Отложенный ответ проверяет конкретную заявку.

Проверки: тесты клиентских действий и реальных функций API в изоляции,
существующие тесты уведомлений/дат, компиляция Python. Live Telegram и
production не запускались; публикация и перезапуск — отдельный шаг владельца.
