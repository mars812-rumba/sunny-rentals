# Техническое задание для Codex: SEO-рефакторинг каталога + GEO/LLM-видимость sunny-rentals.online

## Контекст
Сайт: https://sunny-rentals.online (Next.js). Каталог из ~61 карточки конкретных единиц транспорта. Проблема: Google Search Console показывает ~60 страниц в статусе "Обнаружена, не проиндексирована" — почти весь каталог. Причина: множественные near-duplicate карточки одной модели (разные годы/цвета/комплектации транспорта на отдельных URL с одинаковым шаблоном текста, идентичными блоками FAQ и структурой).

Пример дублей внутри одной модели:
- Toyota YARIS: `/cars/toyota-yaris/`, `/cars/toyota-yaris-2022-black/`, `/cars/toyota-yaris-2022-white/`, `/cars/toyota-yaris-2023-blue/`, `/cars/toyota-yaris-white-sedan/`
- Toyota VELOZ: 4 варианта
- Mazda MAZDA2: 3 варианта
- Nmax155: 3 варианта

Цель: сохранить возможность бронирования конкретной физической машины (это ключевая ценность продукта — "видишь машину, видишь цену"), но убрать SEO-дублирование через модель master/detail + canonical, плюс подготовить сайт к цитированию AI-поисковиками и LLM-агентами (ChatGPT, Perplexity, Google AI Overview, Claude и т.д.).

## Статус внедрения — 8 августа 2026 года

Бриф реализован с поправками, которые защищают достоверность данных и стабильность URL:

- 61 конкретная единица транспорта сгруппирована в 36 устойчивых модельных групп;
- master выбирается детерминированно по стабильному slug, а не по меняющимся году,
  количеству фото или промобейджу;
- sitemap содержит только 36 master-страниц на каждом языке; detail-страницы сохранены,
  работают с собственными фото и Telegram deep-link, имеют `index,follow` и canonical на master;
- на страницах групп добавлен выбор конкретного варианта по фото, году, цвету, цене и депозиту;
- master-страницы получили фактические уникальные сводки и вопросы на основании состава группы;
- schema использует `ProductGroup` + `hasVariant` для групп и `Product` + `Offer` для
  конкретных машин; неподтвержденное наличие в `Offer` не публикуется;
- добавлен `/llms.txt`; существующий wildcard в `robots.txt` уже разрешает публичные страницы
  всем краулерам, поэтому отдельные дублирующие секции для AI-ботов не добавлялись;
- не опубликованы неподтвержденные адрес, юридические данные, отзывы, тариф без депозита и
  выдуманные характеристики моделей.

После сборки sitemap содержит 104 canonical URL: 72 модельные страницы RU/EN, 28
коммерческих и информационных страниц RU/EN, а также 4 главные страницы и каталога RU/EN.

## ЧАСТЬ 1. Схлопывание дублей (master/detail)

### 1.1. Логика группировки
Написать скрипт группировки существующих карточек по модели (нормализация имени: марка + модель без года/цвета/комплектации, например `toyota-yaris-2022-black` → группа `toyota-yaris`).

Для каждой группы:
- Выбрать master-карточку: приоритет — карточка с наибольшим годом выпуска, при равенстве — с максимальным числом реальных фото или пометкой "Хит".
- Остальные карточки группы — detail-страницы (unit-страницы конкретной физической машины).

### 1.2. Canonical
- На всех detail-страницах группы проставить `<link rel="canonical" href="{master_url}">`.
- Master-страница сохраняет self-canonical.
- Detail-страницы остаются полностью рабочими (бронирование, свои фото, свой urlkey в Telegram deep-link `?start=sr2_...`) — canonical влияет только на индексацию, не на функциональность.

### 1.3. UI на master-карточке
Добавить блок "Другие варианты этой модели в наличии" — карусель/список с превью фото, цветом, годом, ссылкой на конкретную detail-страницу. Это сохраняет UX выбора конкретной машины при заходе с сайта, а не только через AI-бота.

### 1.4. Sitemap
- В `sitemap.xml` оставить только master-URL моделей (фактически 36 моделей вместо 61 единицы транспорта).
- Detail-страницы из sitemap убрать (они всё ещё доступны по прямой ссылке/из UI, но не продвигаются в индекс отдельно).
- Добавить `lastmod` по дате последнего обновления цены/фото.

### 1.5. Robots/meta на detail-страницах
Проверить, что на detail-страницах остаётся `index,follow` (canonical сам разрулит консолидацию — жёсткий `noindex` не нужен, он режет передачу веса на master).

### 1.6. Контент master-карточки — убрать шаблонность
Текущий паттерн одинаков у всех моделей:
> "Экономичный городской автомобиль с понятными габаритами и лёгкой парковкой." + идентичный блок из 5 FAQ с подстановкой имени модели.

Для каждой master-карточки написать (можно генерировать через LLM с чётким брифом по модели, но с уникальными фактами):
- 2-4 предложения о реальных особенностях модели для использования на Пхукете (расход, посадка, багажник, для какого маршрута/сценария подходит — пляжи/город/дальние поездки).
- Минимум 1 уникальный факт, которого нет у соседних моделей в том же классе (не общие фразы вроде "комфортный и надёжный").
- FAQ можно оставить структурно похожим (это ок для UX), но 1-2 вопроса сделать модельно-специфичными (например про клиренс для SUV, про багажник для 7-местных, про запас хода для электро BYD Seal).

## ЧАСТЬ 2. Что ещё подкрутить в контенте для силы сайта

1. **Страницы под конкретные сценарии (уже частично есть)** — `long-term-car-rental-phuket`, `car-rental-with-child-seat-phuket`, `phuket-airport-car-rental`. Расширить набор: аренда для пар/медового месяца, аренда без депозита (если есть тариф), аренда на 1 день, мотобайк vs авто для конкретных районов (Патонг, Раваи, Ката).
2. **Живые отзывы с деталями** — не "отличный сервис", а конкретика (какая машина, маршрут, срок). Google и LLM выше доверяют специфичным свидетельствам, чем общим.
3. **Раздел "Правила дорожного движения на Пхукете" / гайд для арендатора** — контент-магнит, который реально ищут и на который ссылаются другие сайты и LLM при ответе на вопросы "аренда авто в Таиланде".
4. **Актуальные цены с датой обновления** — уже есть "Стоимость от 3 августа" на карточках, это хорошо для трастовости, сохранить паттерн везде.
5. **О компании / физический адрес / контакты явно на отдельной странице** — усиливает E-E-A-T (Experience, Expertise, Authoritativeness, Trust) для Google и доверие для LLM при цитировании.

## ЧАСТЬ 3. GEO — чтобы нейросети рекомендовали и цитировали сайт

GEO (Generative Engine Optimization) — оптимизация под то, чтобы LLM (ChatGPT, Perplexity, Google AI Overview, Claude при веб-поиске и т.д.) при ответе на запросы вроде "где арендовать машину на Пхукете" ссылались на sunny-rentals.online.

### 3.1. Файл `llms.txt`
Разместить `/llms.txt` в корне домена (аналог robots.txt, но для LLM-краулеров — стандарт предложен llmstxt.org, поддерживается частью агентов и сборщиков контекста). Структура:

```
# Sunny Rentals — Аренда авто и байков на Пхукете

> Сервис аренды конкретных автомобилей и мотобайков на Пхукете с бронированием через Telegram. 61+ единиц транспорта, сезонные тарифы, реальные фото каждой машины.

## Каталог
- [Автопарк](https://sunny-rentals.online/cars/): полный список доступных авто и байков
- [Аренда на месяц](https://sunny-rentals.online/long-term-car-rental-phuket/)
- [Аренда с детским креслом](https://sunny-rentals.online/car-rental-with-child-seat-phuket/)
- [Трансфер из аэропорта](https://sunny-rentals.online/phuket-airport-car-rental/)

## Условия
- [Условия аренды](https://sunny-rentals.online/rental-terms/)
- [Страховка](https://sunny-rentals.online/insurance/)
- [Депозит](https://sunny-rentals.online/deposit/)
- [Доставка](https://sunny-rentals.online/delivery/)
- [FAQ](https://sunny-rentals.online/faq/)

## Контакты
Telegram: https://t.me/webapp_rent_bot
WhatsApp: +66 84 203 9140
```

Важно: llms.txt — это не гарантия индексации/цитирования (сейчас ни один крупный LLM-провайдер официально не подтвердил, что использует именно этот файл как сигнал), но это дешёвая и растущая по поддержке практика — стоит сделать, вреда нет.

### 3.2. Что реально влияет на цитируемость LLM (в порядке значимости)
1. **Структурированные данные (Schema.org / JSON-LD)** — самое важное. Добавить на карточки:
   - `Product` + `Offer` (цена, валюта, наличие) на каждую master-карточку.
   - `FAQPage` на блоки с вопросами-ответами (у тебя уже есть готовый FAQ-контент — просто оборачивается в разметку).
   - `LocalBusiness` / `AutoRental` на главной и странице контактов (адрес, телефон, часы работы, гео-координаты).
   - `BreadcrumbList` на карточках.
   Это то, что Google AI Overview и Perplexity реально парсят для генерации ответов с цитатой.
2. **Явные, вырванные из контекста цитируемые факты.** LLM охотнее цитируют страницы, где ответ на вопрос сформулирован одним самодостаточным предложением (как в твоих FAQ-блоках — это уже хороший паттерн, усилить его на новых страницах-гайдах).
3. **Свежесть и явные даты.** Указывать "обновлено [дата]" на страницах с ценами/условиями — LLM-поисковики (особенно с веб-поиском) предпочитают недавно обновлённый контент.
4. **Внешние упоминания и бэклинки.** LLM, использующие веб-поиск (Perplexity, ChatGPT с browsing, Claude), в основном опираются на то, что индексирует обычный поиск + на авторитетность источника (упоминания на трэвел-форумах, Reddit r/phuket, тревел-блогах, TripAdvisor-подобных площадках). Без этого даже с идеальной разметкой шансы на цитирование низкие для нового домена.
5. **Понятная семантическая структура страницы** (h1/h2/h3, списки, таблицы) — уже неплохо реализовано в текущей вёрстке.

### 3.3. Дополнительно
- Открыть доступ известным AI-краулерам в `robots.txt` явно (если сейчас не заблокированы): `GPTBot`, `PerplexityBot`, `ClaudeBot`, `Google-Extended`, `CCBot`. Проверить и убрать `Disallow`, если он есть по умолчанию у хостинга/CMS.
- Убедиться, что контент рендерится в HTML при первой загрузке (SSR, что для Next.js уже так и есть), а не только через client-side JS — большинство AI-краулеров не исполняют JS.
