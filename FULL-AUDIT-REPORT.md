# Sunny Rentals — SEO-аудит

Дата: 18 октября 2026, около 18:00 UTC. Объект: живой
[sunny-rentals.online](https://sunny-rentals.online/), не локальная сборка.
Scope: full-site технический обход sitemap + выборочная оценка контента и браузера.
Тип бизнеса: локальный сервис подбора/аренды транспорта на Пхукете.
Аудит выполнен установленным `seo`-скиллом, его скриптами и Chromium/Playwright.
Изменений сайта, публикаций, git commit/push, перезапусков и правок планировщика нет.

## A. Результат

Техническая основа хорошая: все 110 канонических страниц sitemap доступны,
контент есть в исходном HTML, языковые альтернативы взаимны, статьи доступны
из коллекций. Подтверждённых глобальных блокировок индексации не обнаружено.
Это НЕ подтверждение фактической индексации Google или наличия поискового трафика.

Главные три задачи:

1. Исправить обработку несуществующих адресов: сейчас они возвращают главную с HTTP 200.
2. Исправить `html lang` всех 55 английских страниц: сейчас указан русский язык.
3. Исправить превью главных страниц: отсутствующие Open Graph-поля и русский Twitter-текст у EN.

Три возможности роста: полезные описания статей, более лёгкие мобильные изображения,
доступные сведения об операторе сервиса/контактах/обработке персональных данных.
Критических подтверждённых сбоев существующих канонических страниц: 0 в этом обходе.

Общий балл: **недостаточно данных**. В частности, нет CrUX/Search Console и оценки
реальной индексации; PageSpeed API вернул ошибку. Число вроде «85/100» создало бы
ложную точность. Категории ниже оцениваются наблюдаемыми проверками, не прогнозом позиций.

### Что уже сделано хорошо

- `robots.txt` доступен, разрешает публичный сайт, исключает служебные разделы и
  объявляет sitemap. HTTP → HTTPS работает одним 301 без петли.
- Все 110 sitemap URL имеют self-canonical. В sitemap нет обнаруженных перенаправлений,
  noindex или дублирующихся title/description. Фактическая точность lastmod по каждому
  историческому изменению не проверена.
- `/blog/choose-car-rental-phuket-reviews/` открывает статью и canonical указывает
  на `/articles/choose-car-rental-phuket-reviews/`. Canonical конкретного варианта
  машины на master-модель — намеренная консолидация, не автоматическая ошибка.
- Обе опубликованные статьи имеют полноценный RU/EN текст, видимые авторство и
  даты, BlogPosting JSON-LD, обложки и контекстные внутренние ссылки.
- В зимовке есть семь районов, сравнительная таблица, три ИИ-иллюстрации с
  объяснением происхождения и ссылки на источники. В браузере все картинки загрузились
  после прокрутки. Отложенная загрузка вне экрана не является поломкой.
- Все 11 якорей содержания зимовки существуют; нажатие прокручивает к разделу.
  Переключение EN → RU открывает ту же статью, а не общий список.
- В шести браузерных проверках нет uncaught JS page errors и горизонтального
  переполнения документа. Широкая таблица прокручивается локально, как задумано.
- ProductGroup Toyota Yaris содержит конкретные варианты/фото/ставки. Минимум
  517 THB соответствует показанной тарифной сетке; наличия `InStock` не обещано.
  Депозит отделён от аренды, доступность требует подтверждения менеджером.

### Производительность: наблюдения, не сертификация CWV

Однократный headless Chromium рядом с сервером, без мобильного CPU/network throttling:
главная — последний LCP-кандидат 2.892 s desktop / 2.664 s mobile (атмосферный фон),
EN-коллекция — 0.500 / 0.384 s, EN-зимовка — 0.480 / 0.384 s.
Наблюдаемый CLS: 0.00065–0.05793. INP репрезентативно не измерен.
Это диагностические события PerformanceObserver, не Lighthouse и не p75 реальных
посещений. Не следует объявлять CWV пройденными или проваленными на их основании.

### Контент, schema и AI-поиск

У контента есть практическая структура и путь в каталог/условия. Следующее усиление —
проверяемая информация о команде и конкретные полезные данные, а не выдуманные биографии
или искусственное увеличение объёма. Наличие AI-изображений само по себе не проблема.

FAQPage в коммерческих условиях/моделях не следует обещать как Google FAQ rich result.
Это вопрос eligibility, не сломанная JSON-разметка и не причина срочно удалять FAQ.
[Google: ограничения FAQ rich results](https://developers.google.com/search/blog/2023/08/howto-faq-changes).

`llms.txt` и `llms-full.txt` доступны. Явные отдельные правила AI-ботов отсутствуют,
они наследуют общие правила. Это выбор политики доступа, не SEO-ошибка. Не требуется
создавать специальную AI-разметку ради появления в Google AI-поиске.
[Google: AI features and your website](https://developers.google.com/search/docs/appearance/ai-features).

## D. Ограничения и исключённые ложные тревоги

- Нет доступа к Search Console/Яндекс Вебмастеру, аналитике, данным заявок, внешним
  ссылкам и Business Profile. Не сделаны выводы о позициях, санкциях, трафике,
  реальной индексации или репутации. Конкурентный и keyword-аудит не входят в запуск.
- PSI API HTTP 400 — ограничение проверки, не ошибка сайта. Проверены две ширины,
  не все устройства/браузеры; формы не отправлялись, бронирования не создавались.
- В материалах скилла есть справочники старше 90 дней. Их спорные утверждения о
  штрафах, обязательных объёмах и процентах AI-видимости не перенесены в выводы.
- `article_seo.py` не распознал видимые автора/даты; `validate_schema.py` ошибочно
  назвал корректную оболочку `@graph` отсутствием `@type`. Эти тревоги исключены.
- «Обязательно 1500 слов», английский Flesch для русского текста и кандидаты в
  сиротские страницы из неполного обхода не использованы как доказательства.
- Mojibake в некоторых JSON штатных requests-скриптов — ошибка декодирования
  инструмента, не текста сайта: UTF-8 HTML и Chromium показывают нормальную кириллицу.
- Квадраты вместо emoji-флагов в Linux Chromium не классифицированы как ошибка сайта:
  вероятно отсутствие шрифта в среде проверки.
